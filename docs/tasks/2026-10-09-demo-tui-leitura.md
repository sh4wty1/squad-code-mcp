# Demo da TUI leitura com logs das frames

**Por quê:** ver a TUI leitura funcionando de fato. Sem sessões do squad ativas, o broker real não tem eventos e a tela abre sem nada para mostrar.
**O quê:** `bun run demo [frame]` em `broker/` abre a TUI sobre o log de uma frame de teste, sem broker e sem squad, em um único comando. Sem argumento usa a frame `01`; um nome que não existe lista todas as frames e sai com código 1.
**Como:** novo `broker/tui/demo.ts`: sobe `Bun.serve` em `127.0.0.1` numa porta livre, serve em `GET /events` os eventos de `LOGS[frame]` (`broker/test/frames/logs.ts`) com os horários deslocados para que o relógio da frame seja o agora, grava a tabela `PRICES` das frames num arquivo temporário e inicia `tui.ts` como processo filho com `SQUAD_PORT` e `SQUAD_PRICES` apontando para eles. `last_seq` é arredondado para cima porque as frames têm `seq` fracionário e o leitor da TUI exige inteiro. Script `demo` adicionado em `broker/package.json` e parágrafo na seção TUI de `broker/README.md`. O script temporário da primeira iteração, no scratchpad da sessão, foi substituído por este.
**Verificação:** Linux, Bun 1.3.14. `bun run demo 22g` em pseudo-terminal de 130×42 via `script` desenhou a tela principal com `broker ● conectado`, os avisos de permissão e gate pendentes, agentes e feed, e saiu com código 0 ao receber `q`. `bun run demo nope` listou as frames e saiu com 1. `bun node_modules/typescript/bin/tsc --noEmit` saiu com 0. A suíte `bun test` não foi rodada de novo: nenhum arquivo coberto por ela mudou. Navegação por teclado além de `q` não foi exercitada. Windows não foi executado.
**Pendências:** tela cheia com fonte padrão deu 39 linhas no terminal do VS Code e no do Linux, uma abaixo do mínimo de 40: o usuário quer melhorar isso depois (o mínimo 120×40 é decisão do design). teste interativo manual fica com o usuário. Commit feito na branch `feat/tui-leitura`, que é a do PR 8: o demo entra no diff desse PR. Sem teste automatizado para o demo.
